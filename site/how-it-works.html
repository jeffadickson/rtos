How NexRT schedules work, how to write an application, and where drivers meet the CPU.

This is a host-side developer guide generated from the checked-in examples and assembly. RISCue firmware cross-builds; hardware execution, other CPU ports and board qualification remain separate work.

What the kernel does

Static application threads→Scheduler + optional IPC→CPU port→Board hardware

Before scheduling, main registers permanent thread control blocks and stacks. start() seals the registry, creates private idle state, configures the timer and dispatches. At each scheduling boundary the highest ready priority wins. Larger priority numbers take precedence; equal priorities rotate when requested. A sleeping or blocked thread permits other work to run.

The kernel has no general heap, runtime thread creation or stack growth. Optional queues copy bounded values, mutexes serialize device transactions with priority inheritance, events represent readiness, and semaphores count tokens. These single-hart mechanisms do not provide SMP locking or DMA coherency.

The measured nano image is 3812 bytes of code/initialized data and 9072 bytes of committed RISCue RAM, including the 4096-byte boot reserve. This guide and web services are excluded from that minimal image.

Write and build an application

Start with one function, one control block and one fixed stack. The following is the actual nano example. Set machine_timer_hz to the real timer frequency and verify the timer addresses/RAM map before board execution.

#include "rtos.hpp"
// One thread writes this debugger-visible counter. Volatile is not synchronization.
volatile uint32_t nano_iterations;
namespace {
// Permanent boot-owned storage; the kernel borrows these objects forever.
rtos::Thread task;
rtos::Stack<512> stack; // Example size, not a proven worst-case stack bound.
// EXAMPLE ONLY: replace with the actual board mtime frequency before execution.
constexpr uint32_t machine_timer_hz = 10'000'000;
void work(void*) {
    for (;;) {
        ++nano_iterations;
        rtos::sleep_for(1); // Tick units; blocking permits private idle to execute.
    }
}
}
extern "C" int main() {
    // Higher numeric priority wins; nano reserves one application registry slot.
    if (!rtos::create(task, work, nullptr, 1, stack, "nano")) return 1;
    rtos::start(machine_timer_hz); // Non-returning timer setup and first dispatch.
}

cmake --build --preset host --target native_tools
cmake --preset nano \
  -DRISCV_TOOLCHAIN_PREFIX=/path/to/toolchain/bin/riscv64-unknown-elf- \
  -DRTOS_PREBUILT_NATIVE_TOOLS=build/host/native-tools
cmake --build --preset nano

Run from the repository root in Linux/WSL with CMake, Ninja, .NET 10 Native AOT prerequisites and a suitable RV32 toolchain. The result is build/nano/demo.elf plus demo.map. The build audits allocator/constructor symbols. Watch nano_iterations in a board debugger after verifying your loader and FPGA design.

Communicate by copying a small value

#include "rtos_ipc.hpp"
struct Sample { uint32_t channel; int32_t value; };
static rtos::Queue<Sample, 4> samples;
// Producer: check full explicitly.
auto sent = samples.send({1, 42});
// Consumer thread: timeout is ticks; failure leaves sample unchanged.
Sample sample{};
auto received = samples.receive(sample, 100);

Enable RTOS_SYNC for these services; enable RTOS_LOGGING for bounded queued printf. Keep pointee lifetime explicit if a message contains a pointer. Use one permanent output thread and one logger for a shared console.

Write a small driver

A driver owns register access, clock/reset setup, operation deadlines and recovery. The kernel supplies scheduling and ownership. Construct one permanent driver per physical device and share that object among its client threads.

  1. Obtain the hardware register map, access widths, endianness, reset values and timing contract.
  2. Keep MMIO in one board-facing class. volatile preserves accesses; it does not make a multi-register operation atomic or supply a bus fence.
  3. Wrap the whole command/data/status transaction with DeviceTransactions, not each individual register.
  4. Bound ownership waits and hardware completion separately. A stalled AXI load requires interconnect timeout/recovery; a software timeout cannot rescue a non-returning bus transaction.
  5. Return explicit results and retain fault state until hardware is known safe. Never silently reuse an owner-dead device.
class Device {
    rtos::DeviceTransactions transaction_;
public:
    rtos::Result execute(uint32_t command) {
        return transaction_.transact(100, [&]() {
            // Board code: write command, wait to a bounded deadline,
            // read status, and acknowledge completion.
            // Replace this placeholder with your verified register protocol.
            (void)command;
            return rtos::Result::invalid;
        });
    }
};
static Device shared_device;

The placeholder deliberately does not claim to perform I/O. Thread clients call the same instance. The acquisition timeout covers the mutex, not callback duration. ISR code must only use documented nonblocking APIs after the port provides verified dispatch/acknowledgement. The present RISCue port enables its machine timer only; a completion event alone does not install a peripheral interrupt handler.

For a first integration, prefer bounded polling and a single owning worker. DMA is a later adapter with explicit buffer ownership, address/cache policy, completion and cancellation/quiescence. PCIe/SpaceVPX additionally needs versioned peer messages and fault/window isolation. No generic cache flush or bus address is guessed.

How preemption crosses assembly

Reset disables interrupts, establishes sp/gp, clears BSS and calls main. There is no constructor runner or ROM-to-RAM data copy. A loader must place initialized data correctly.

A trap may interrupt any live register. The vector saves every integer register and machine continuation state before calling C++. The scheduler returns a different saved-frame pointer; assembly changes stacks only after the C++ call unwinds, restores the selected frame and executes mret.

Frame bytesState
0Unused x0 slot
4..124x1..x31; original sp at byte 8, restored last
128mepc; ECALL advances by four, timer keeps the interrupted PC
132mstatus; MIE remains clear during restoration
136..143Alignment padding; frame total is 144 bytes

The frame constructor uses the same layout. Initial status 0x1880 selects machine mode with MPIE set and MIE clear. First mret enables interrupts after restore. Runtime traps use each interrupted thread's stack; the boot reserve is not a separate ISR stack.

Inline assembly and timer operations
#pragma once
#include <stddef.h>
#include <stdint.h>
extern "C" void rtos_vector();
namespace rtos::port {
using InterruptState = uint32_t;
/** Atomically read mstatus and clear MIE (bit 3) on this hart. The '=r' output
 * permits compiler register allocation; immediate 8 is the CSR bit mask. The
 * memory clobber orders compiler RAM accesses, not hardware MMIO, DMA or SMP.
 */
inline InterruptState mask_interrupts() { InterruptState previous; asm volatile("csrrci %0, mstatus, 8" : "=r"(previous) :: "memory"); return previous; }
/// Restore saved MIE only. Nested callers unwind in order with MIE still masked.
inline void restore_interrupts(InterruptState previous) { if(previous & 8) asm volatile("csrsi mstatus, 8" ::: "memory"); }
/// Power/wait hint; current RISCue may implement WFI as a NOP.
inline void idle() { asm volatile("wfi"); }
/// Fail closed: disable interrupts and remain in the hint loop forever.
[[noreturn]] inline void halt() { (void)mask_interrupts(); for(;;) idle(); }
/// Read split MMIO high/low/high; retry on rollover to avoid a torn RV32 value.
/// Board integration must provide accessible, ordered 32-bit timer registers.
inline uint64_t time_now() {
    auto* timer=reinterpret_cast<volatile uint32_t*>(RTOS_MTIME_ADDRESS);
    uint32_t hi,lo,again;
    do { hi=timer[1]; lo=timer[0]; again=timer[1]; } while(hi!=again);
    return (uint64_t(hi)<<32)|lo;
}
/// High=max, low, final high prevents a transient early compare on this board.
/// This assumes ordered MMIO; another port must supply its own verified ordering.
inline void arm(uint64_t deadline) {
    auto* compare=reinterpret_cast<volatile uint32_t*>(RTOS_MTIMECMP_ADDRESS);
    compare[1]=0xffffffffu; compare[0]=uint32_t(deadline); compare[1]=deadline>>32;
}
/** Construct context.S's 36-word frame in validated permanent stack storage.
 * Slot 2 is the original stack top, slot 32 the entry trampoline. 0x1880 means
 * MPP=M, MPIE=1, MIE=0: the first mret enables IRQs after restoring all registers.
 * gp/tp inherit bootstrap register values; tp preservation is not TLS support.
 * See the Sphinx assembly-port frame table before changing either implementation.
 */
inline uint32_t* initialize_context(void* stack,size_t bytes,void (*entry)()) {
    auto* frame=reinterpret_cast<uint32_t*>(static_cast<char*>(stack)+bytes)-36;
    for(unsigned i=0;i<36;++i) frame[i]=0;
    frame[2]=reinterpret_cast<uintptr_t>(frame+36);
    asm volatile("mv %0, gp" : "=r"(frame[3])); // Allocated register output is stored in x3's slot.
    asm volatile("mv %0, tp" : "=r"(frame[4])); // Preserve bootstrap x4 without inventing a TLS base.
    frame[32]=reinterpret_cast<uintptr_t>(entry); frame[33]=0x1880u;
    return frame;
}
/// Set the aligned direct mtvec using an allocated 'r' operand and compiler barrier.
inline void install_vector() { asm volatile("csrw mtvec, %0" :: "r"(&rtos_vector) : "memory"); }
/// Enable MTIE (bit 7) only; external interrupt sources remain disabled.
inline void enable_timer() { asm volatile("csrw mie, %0" :: "r"(0x80u) : "memory"); }
/// A synchronous 32-bit ECALL traps even with MIE clear; memory clobber orders RAM.
inline void reschedule() { asm volatile("ecall" ::: "memory"); }
/// Machine-mode ECALL: exception code 11, interrupt bit clear.
inline bool is_yield(uint32_t cause) { return cause==11; }
/// Machine timer: interrupt bit 31 set plus exception code 7.
inline bool is_tick(uint32_t cause) { return cause==0x80000007u; }
/// Skip only ECALL's four bytes; a timer trap retains the interrupted PC.
inline void resume_after_yield(uint32_t* frame) { frame[32]+=4; }
}

Inline assembly uses compiler-allocated registers and memory clobbers where required. A memory clobber orders compiler operations; it is not a hardware fence, DMA cache operation or multicore lock. Nested traps, user mode, TLS and floating-point/vector context are outside this port.

Port the CPU and the board separately

Tang Nano 9K is an FPGA board, so its selected soft core determines the interrupt ISA, timer and memory map. Classic MicroBlaze is a separate architecture from MicroBlaze V. Do not substitute RISC-V assembly for a classic MicroBlaze context switch.

A port needs an exact hardware design/export, compiler ABI, endianness, RAM, timer frequency/registers, interrupt routing, startup/vector policy and cache policy. Until these are checked, configuration status stays provisional/planned. Cross-build evidence does not establish board execution.
